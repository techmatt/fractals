Run the pipeline yourself

Everything on this site was made by the code in the fractal-wallpapers repository, and you can run all of it yourself. This page walks through a fresh install on one machine and shows a small sample of what each stage writes, so you can check your own run against it. I ran each stage for about ten minutes. That is enough to see every file and a first small gallery, but nowhere near enough to find many good wallpapers.

You do not need a GPU. The judges run several times faster with one, but most of the time goes to rendering, which runs on the CPU either way. The whole example takes about 45 minutes on a CPU install and about 27 with CUDA, and leaves about 1.1 GB on disk.

The pages embedded below are the ones the repository's own commands write, taken from my run. Follow one picture, at the end, traces the twelve pictures of the final gallery back through every file, along with a few that were rejected along the way. Each file's fields are defined in FORMATS.md in the repository.

Install

The code is Rust and Python. The Rust engine draws every picture, and you can build and use it alone if rendering is all you want. Python runs the pipeline around it and the judges, which are neural networks in PyTorch.

The CPU and CUDA installs differ only in which PyTorch they pull.

git clone https://github.com/techmatt/fractal-wallpapers
cd fractal-wallpapers
uv sync --extra models --extra solve              # CPU torch, any machine
uv sync --extra cuda --extra solve                # or: CUDA torch, an NVIDIA card (Windows, Linux x86_64)
cargo build --release --manifest-path engine/Cargo.toml

Every picture on this site and in Mandelnaut Explorer carries a link that holds its whole recipe. This command reads the link's text and draws the same picture on your machine, at any size, without going online.

Walk for locations

The walk explores each fractal family for a fixed amount of time and records the places it finds, and the location judge then scores each place. No two walks find the same places.

In my run, ten minutes of walking found 4,022 places, and ten minutes of mining made 327 candidate pictures from the best 109 of them. Only 2 of those pictures were good enough for the gallery at its usual standard.

Mining takes the best-scoring places, tries rendering modes and palettes on each, and keeps the pictures the wallpaper judge likes.

options:
  -h, --help            show this help message and exit

what to call it:
  `run` rewrites --name every time; `record` stamps --solve-name and never writes over it

  --name NAME           what to call this pass's output directory (default `n<N>`). …

how big, and how much of the pool it reaches:
  --n N                 how many wallpapers to seat (default 20, the size a leg is read at). …
  --locations COUNT     let the pass reach only this many strongest CLUSTERS — a kept place plus
                        every place the neutral pre-selection folded into it — ranked by their
                        best candidate on the fine head's p_fine where it has read the row and raw
                        P(>=4) where it has not. …
  --rows-per-seat ROWS  how many view rows each stratum keeps per seat it could contribute
                        (default 2). …
  --draw-seed SEED      the seed the view's band-blind stride offsets are drawn under (default 0).
                        …
  --allow-unranked      choose even though the key cannot read every clearing candidate. …
  --collection NAME     seat ONE COLLECTION — a hue family or a production mode — at the size
                        `curation.targets.TARGETS` sets for it. …
  --fine-bar SCORE      narrow the pool to the rows the gallery-grade head reads at p_fine(>=4) >=
                        SCORE, BEFORE anything else runs — the per-mode bars, the neutral pre-
                        selection and the view are all taken over what is left, so a barred pass
                        is a whole pass and not a filtered reading of an unbarred one. …
  --force-fill          seat as many as an EARLY pool allows: the fine bar and the per-mode bars
                        stop refusing and the best rows available seat, while every distinctness
                        rule still holds. …
  --forced PATH         a MANIFEST of candidate keys, one per line, this pass lifts to the top of
                        the fine column BEFORE the bar, the neutral pre-selection and the cascade
                        — so a forced row clears `--fine-bar`, is its cluster's survivor and is
                        offered ahead of every unforced row. …
  --no-pins             seat NONE of the pinned list, for a comparison. …
  --fold {pool,delete}  what the neutral pre-selection does with a place it folds into another. …

the demands:
  every one of these is counted with its shortfall recorded: unfilled beats padded, and no
  demand is ever met by a fallback leg

  --target CELL=FRACTION
                        demand that at least this share of the REALIZED seats be dominant in this
                        colour cell. …
  --mode-floor SEATS    an ARTIFICIAL flat mode floor, one number for every accepted mode. …
  --flat-floor          solve under the FLAT mode floor instead of the per-mode rule — floor(n /
                        100) seats for every accepted mode, which is what every gallery before
                        2026-08-31 was seated under. …
  --group-cap {identity,proportional}
                        which palette-group cap to run under. …
  --spiral-cap SHARE    cap the share of seats filled from a location the spiral probe calls a
                        spiral: at most ceil(SHARE * seats filled), the same spelling a colour
                        target is stated in. …
  --cell-floor {on,off}
                        the COLOUR FLOOR: at least floor(kf * t * seats filled) seats dominant in
                        each of the 48 chromatic cells — kf = 1 against the ceiling's k = 3, one
                        fair share against three, so 20 of a thousand seats where the allowance is
                        63. …
  --mode-ceiling MODE=SHARE
                        cap the share of seats one MODE may take: at most ceil(SHARE * seats
                        filled), the spiral cap's own arithmetic and the same spelling a colour
                        target is stated in. …

a themed gallery:
  one dominant colour cell at the relaxed bar; the other two are ignored without --themed

  --themed CELL         choose a THEMED gallery: one dominant colour cell, over a pool of the rows
                        that cell's dominance block claims, at the RELAXED bar — P(>=3) >= 0.5 for
                        every accepted mode rather than the per-mode rule, because a single-cell
                        pool is q3-grade material and at the per-mode bars there is no pool. …
  --themed-cap SEATS    the palette-group cap a THEMED pass runs under, overriding the computed
                        one. …
  --themed-radius COSINE
                        the radius the themed diversity rule refuses inside (default 0.07). …

  --neutral-radius COSINE
                        the neutral pre-selection radius applied at pool construction (default
                        0.02). …
  --no-preselection     choose from the whole clearing pool, with no neutral pre-selection
  --no-diversity        choose without the diversity rule, which is the only rule that opens a
                        picture. …

  --key {cascade,p_ge4}
                        the sort key the pool is walked in AND the quantity the objective is
                        stated in. …
  --explain-keys PATH   a MANIFEST of candidate keys, one per line, whose fate this pass records
                        ONE AT A TIME into `rejection.explained` — every key named comes back
                        `seated`, `not in the pool`, or the first rule that refused it. …
  --no-swap             take the greedy seed and stop. …
  --swap-seconds SECONDS
                        a wall budget for the SWAP LOOP alone. …
  --augment {on,off}    the augmenting-chain stage: eject one seat, insert TWO in its room. …
  --augment-depth {2,3}
                        how long a chain may be: 2 is one ejection and two inserts, 3 is one more
                        eject/insert pair. …
  --augment-seconds SECONDS
                        a wall budget for the AUGMENT STAGE alone. …
  --explain-seats-of NAME
                        an earlier solve record whose seats this pass explains ONE AT A TIME, into
                        `rejection.explained`: every key it seated comes back either `seated` or
                        with the rule that refused it here. …
